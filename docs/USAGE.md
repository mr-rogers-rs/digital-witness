# First use and personal storage

The setup proceeds through Welcome, How it works, PIN, Permissions, Background recording, Backup destination, Network privacy, and Done. Set a personal app PIN. Grant camera permission and microphone permission only if recording audio. The language follows the phone or the explicit language choice.

Evidence mode is the fresh-install default and retains additional device/environment metadata and signed proofs. Anonymous mode is available in Settings → Advanced settings; it reduces selected metadata and disables GPS, but does not conceal your cloud account, network address or the contents of the scene. Existing saved mode choices remain unchanged. Preview, torch and audio controls are available on the recording screen. Start recording while the app is visible, then lock the phone if desired. Check the recording and upload status when stopping.

The Background recording step offers Android battery-exemption settings and, where applicable, manufacturer instructions. Return to setup after changing the settings; continuing without an exemption is allowed. Recording never launches these prompts. The same options remain available in Settings.

Choose your own backup destination. Choose folder is recommended. In Android's file picker, open the top-left menu (☰) to see supported providers. If installed and signed in, a cloud provider such as Google Drive or Dropbox can appear only when it supports writable folder access; installing a provider alone does not guarantee it will appear. A selected folder can be on-device storage or a document provider. A provider accepting a file is not proof it has reached remote storage. Open the remote service and check receipt and playback separately.

Nextcloud setup uses your HTTPS server URL, username and an app password created in your own Nextcloud account. Configure any optional certificate fingerprint from a separately trusted source. WebDAV likewise requires your own HTTPS endpoint and credentials. Dropbox/manual Google Drive options require your own provider application/account credentials as requested by Settings; they do not contain a ready-to-use shared account or authorization project. Validate the chosen provider's permissions, token expiry and refresh behavior before relying on it. There is no central account to connect automatically.

Readable uploads are the fresh-install default: ordinary media/proof files are sent over the configured transport. File encryption is available in Settings → Advanced settings. Existing export policies, including queued-file snapshots, remain unchanged. Recipient encryption instead requires a recipient RSA public key and produces `.jwe` files. Keys held only in Android Keystore cannot be handed to a desktop recipient. For recipient-encrypted delivery use `python tools/recipient_export.py keygen /private/recipient-directory`, enter a passphrase and copy only `recipient-public.pem` into the app's recipient-key field. Keep `recipient-private.pem` on the recipient's computer. Decrypt downloaded files using `python tools/recipient_export.py decrypt --private-key /private/recipient-directory/recipient-private.pem --output-dir /private/decrypted /download/clip.mp4.jwe`.

The fresh-install network policy allows any available Wi-Fi or mobile connection and has Tor disabled. Existing saved VPN/Tor requirements remain unchanged. Choose the network policy in setup or Settings. Tor requires a working configured proxy; an onion address also requires Tor. Explicitly allowing direct Internet delivery changes the privacy tradeoff; use HTTPS for ordinary remote destinations. Pending files remain queued when the chosen policy blocks delivery. A local-only recording choice is also available.

The initial video target is 2000 kb/s with adaptation enabled. Sustained queue growth can reduce the target gradually to 1750 and 1500 kb/s and restore it as delivery catches up. Resolution and frame rate do not change during adaptation. This reduces encoding quality; check readable detail in representative footage. Slow connections can still accumulate a queue. Explicit bitrate settings remain configurable.

Use harmless material to check offline/reconnect delivery, screen locking on battery, audio synchronization and remote playback on each intended device. See [VALIDATION](VALIDATION.md).
